## 2. 三个业务示例与完成标准

以下中文示例用于元信息；英文示例表达相同任务。主 Skill 直接包含下表的核心步骤，参考文档只承载补充说明。

| 示例 | 现有工具与执行路径 | 完成标准 |
| --- | --- | --- |
| 查看我的账号状态和剩余额度。 | `patchxnote_get_current_user({})` → `patchxnote_get_quota_summary({})` | 两项调用均成功，展示服务实际返回的账号状态、额度数值和单位；缺失字段如实说明，一项失败时只报告已取得的结果，不勾选整条通过 |
| 列出我最近五条记录或总结，包含标题、时间和来源。 | `patchxnote_list_memories({"limit":5})`，具体参数以实时 schema 为准 | 返回至多五条真实记录，保留服务返回的来源和时间；不足五条就展示实际数量，空列表正常说明 |
| 将我最近一条有可读总结的记录整理成 Markdown 笔记。 | 列表取得真实记录 ID 和来源 → `patchxnote_render_webhook_message`，传入对应 `memory_id` 和已返回的 `platform` → 根据返回内容整理 | 展示可复制的标题与总结要点；只有内容确实包含待办时才列待办。只返回 ID、元数据或操作教程不算完成 |

用户指定来源时按实时 schema 使用 platform；未指定时保留账号级查询，不固定为 mobile。当前工具包含已保存结果和模型生成结果，因此示例称“记录或总结”，输出不能把所有结果都说成原始录音，不为本轮新增类型筛选能力。

笔记任务先调用 `patchxnote_list_memories({"limit":5})`，根据返回的时间/顺序选择最近候选；用该候选的真实 ID 和来源调用渲染工具，不猜 ID 或平台。只有明确没有可读内容时才检查其他候选；授权、权限或网络错误按其阶段报告，不能通过换记录掩盖失败。若返回下一页且仍需寻找可读总结，可沿用 cursor 继续查询；仅检查了一页时说明检索范围，不断言整个账号没有总结。无需新增分页算法、重试模块或硬编码额外调用配额。

渲染工具返回的正文才是笔记依据；优先使用默认渲染，不传本地 out 路径或 save_draft=true，不触发 webhook 发送。没有合适内容时如实说明，笔记验收仍待补齐。

授权是三条任务的共同前提，不再单独作为“让 AI 打开浏览器”的业务示例。其他已支持能力保留，不因本轮只验三个示例而删减远程工具或其使用说明。
