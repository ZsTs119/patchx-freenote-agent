# WorkBuddy 连接、授权与重连

本包通过平台 OAuth 直接访问远程 MCP。最低 WorkBuddy 版本为 5.0.0，source 为 {{CONNECTOR_SOURCE}}；环境为 {{ENVIRONMENT}}，MCP 地址为 {{MCP_URL}}。

## 首次连接

1. 在 WorkBuddy 安装并连接 Freenote 连接器。
2. WorkBuddy 发起浏览器授权；用户在授权页面完成账号登录并确认授权。
3. 返回 WorkBuddy，等待连接完成并获取工具列表。
4. 完成账号状态和额度示例，实际调用 patchxnote_get_current_user 与 patchxnote_get_quota_summary；成功后继续用户要完成的任务，不额外要求先读取手机记录。

Windows 和 macOS 使用同一条远程接入路线，正常连接不需要安装本地程序或手动创建目录。浏览器未打开或授权中断时，从当前连接器的授权入口重试；不要复用已过期的授权链接。

## 提交授权配置与评测

维护者在平台的授权配置中选择“需要用户授权 / MCP OAuth”，由本人在浏览器登录已有可读总结的账号。确认该授权属于本次版本的连接器及其评测配置；账号或凭据不写入 ZIP，也不发到聊天里。

显示“无需授权”或 initialize 探活成功，只能证明初始化连通；需要页面显示已授权，并有本连接器受保护工具的实际成功结果。其他连接或终端的登录状态不能替代。

授权完成后验证三个示例：账号状态和额度、最近五条记录或总结、最近可读总结转 Markdown 笔记。空列表可以正常返回，但不能替代笔记正文的验证。重连后复用有效授权，再调用账户工具确认。

平台有调试入口时先验证上述示例；若提交授权配置后自动开始质量评测，则按界面提交，并结合真实结果核对任务完成情况。未覆盖的项在可用入口补验，缺少结果时保持待验证，不把包解析、连通自测或提交成功当成质量评测通过。

## 已有连接器升级

保留同一 source，先通过平台更新连接器并重新连接。切换到平台托管授权后，可能需要授权一次；原来终端中已登录不等于新连接器已授权。

若仍使用旧的本地启动入口，确认当前连接器版本；宿主无法直接更新时，通过正常界面移除并重新添加本连接器。无需手工清理安装缓存或修改系统目录，其他连接不受此步骤影响。

## 重连、更新与授权失效

- 正常重连复用平台保存的有效授权，不重复登录。
- 访问凭据到期由平台刷新；明确授权失效时才重新授权。
- 网络或服务暂时不可用时提示重试，不先清除授权。
- 服务端业务更新供此连接直接使用；工具列表变化时刷新或重连。
- 连接地址、授权配置或说明变化可能需要更新连接器包。

取消或超时后停止等待，用户准备好后可以从连接器重试。切换账号或解除授权使用平台提供的入口；仅关闭连接不宣称服务端授权已被撤销。完成新授权后以账户工具确认当前账号。
